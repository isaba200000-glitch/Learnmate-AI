## CRITICAL BUGS IDENTIFIED

### 🔴 BUG #1: Yearly Plan "Not Authorized" Error

**Location:** `artifacts/api-server/src/routes/premium.ts:180-188`

**Symptom:** Users see "Not Authorized" when attempting yearly plan checkout, even with valid Clerk session.

**Root Cause Analysis:**

```typescript
router.post("/premium/whop/checkout/yearly", requireAuth, async (req, res) => {
  const userId = (req as AuthRequest).userId;
  const planId = process.env.WHOP_YEARLY_PLAN_ID;  // ← Missing env var!
  if (!planId) {
    res.status(503).json({ error: "Yearly plan not yet available..." });
    return;
  }
  await createWhopCheckoutSession(req, res, userId, planId, 365, "yearly");
});
```

**Issues:**
1. **Missing Environment Variable:** `WHOP_YEARLY_PLAN_ID` not set in deployment
2. **Returns 503** (Service Unavailable), but frontend error handler may misinterpret as 401 (Unauthorized)
3. **No Premium Tier Visibility:** Frontend doesn't know yearly is unavailable until attempting checkout

**Fix (Priority: CRITICAL)**
- [ ] Set `WHOP_YEARLY_PLAN_ID` in production environment
- [ ] Add endpoint to list available payment tiers (frontend can show before checkout)
- [ ] Improve error messaging to distinguish between auth and config errors

### 🔴 BUG #2: Quiz Images Infrastructure Missing

**Location:** `artifacts/api-server/src/routes/quizzes.ts:261-279` & `artifacts/learnmate/src/pages/quizzes.tsx:560-620`

**Symptom:** Photo quiz and AI-generated quizzes don't display images—only text questions render.

**Root Cause Analysis:**

The photo quiz flow:
```typescript
// Backend receives base64 image
const { imageBase64, totalQuestions, difficulty } = req.body;
// ↓ Sends to OpenAI Vision API
const completion = await openai.chat.completions.create({
  messages: [
    { type: "image_url", image_url: { url: imageBase64 } },
  ],
});
// ↓ Parses JSON response: { subject, questions: [...] }
const parsed = JSON.parse(completion.choices[0].message.content);
const rawQuestions = Array.isArray(parsed.questions) ? parsed.questions : [];
```

**The Issue:**
- Questions are stored in `quiz_questions` table with fields: `question`, `options`, `correctAnswer`, `explanation`
- **There is NO `imageUrl` or `imageData` field** to store associated images
- AI might generate structured answers that reference images, but they're never persisted
- Frontend renders questions but has no image data to display

**Secondary Issue:**
- Course lesson quizzes use same `quiz_questions` schema
- Course system has extensive image generation infrastructure (topics, lessons, step-by-step guides)
- But quiz system doesn't hook into it

**Fix (Priority: HIGH)**
- [ ] Add `imageUrl` (nullable) and `imageType` (nullable) fields to `quiz_questions` table
- [ ] Modify OpenAI prompt to NOT request images (or store generated image URLs)
- [ ] Update frontend quiz renderer to display images when present
- [ ] Add Drizzle migration

## PERFORMANCE OPTIMIZATIONS OBSERVED

### Image Pre-warming (Excellent)
```typescript
// At server startup: generate & cache ~102 images sequentially
export async function prewarmTopicImages() { ... }        // 6 hero images
export async function prewarmLessonImages() { ... }       // 24 lesson illustrations
export async function prewarmLessonStepImages() { ... }   // 72 step-by-step guides
```
**Benefit:** First student to visit a course sees images instantly, not after 30-60s wait.

### Query Caching
- Infinite stale time for images (`staleTime: Infinity`)
- Lesson content cached globally in DB (not regenerated per-user)
- React Query deduplicates concurrent requests

### Rate Limiting
- Free users: 3 lessons/day, 3 photo quizzes/24h
- Graceful 429 responses with upgrade prompts
- Daily usage tracked per Dhaka timezone (supporting Bangladesh-first user base)

### Content Generation Safeguards
- AI content cached after first generation (huge cost savings)
- Lesson generation blocked if usage limit hit (prevents abuse)
- Image generation skips already-cached rows

## SECURITY & COMPLIANCE

### ✅ **Strengths**
- Clerk handles OAuth/SAML securely (no secrets in frontend)
- All API routes require authentication (`requireAuth` middleware)
- Owner-only endpoints check `isOwnerRequest()` 
- Admin password stored securely (never exposed in code/frontend)
- Premium checks are server-side (cannot be bypassed by client)
- Rate limiting & daily quotas enforce fair use
- pnpm has supply-chain security: `minimumReleaseAge: 1440` (1-day window before installing)

### ⚠️ **Considerations**
- Admin password should be rotated regularly
- Whop API keys must be kept secure in env vars
- OpenAI API usage not yet metered (could be expensive if abused; consider adding quota per user)
- Photo attribution (Pexels license) is properly credited in UI ✅
